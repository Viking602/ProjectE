# ProjectE for the project02 instance

Local port of `https://github.com/Viking602/ProjectE`, based on commit
`f432b0c66837759fb0731c9144dc53176b949c5d` (mc1.21.1).

Target: Minecraft 26.1.2, NeoForge 26.1.2.114, Java 25.
Artifact: `ProjectE-26.1.2-1.1.0-project02.3.jar`.
The upstream MIT license and credits are retained. This is an unofficial local build.

## Build

```powershell
. ..\devtools\env.ps1
.\gradlew.bat build
```

Install the JAR without the `-sources` or `-unshaded` suffix. The distributable
includes the API and relocated Commons Math classes. Build dependencies use
Gradle 9.2.1, ModDevGradle 2.0.148, and Shadow 9.3.0. A local Maven mirror under
`../devtools/maven` works around this machine's Java TLS failures.
The build obtains optional JEI, Jade, and Curios compile dependencies from the
instance's `../../mods` directory. TOP 26.1.2_neo-14.0.0 and WTHIT neo-19.0.1
compile dependencies are in `../devtools/projecte-optional`. They are compile-only
dependencies and are not bundled in ProjectE.

## Port changes

- New item/block registration IDs, equipment and indestructible tool components.
- Transactional item/fluid capabilities, including rollback across sided views.
- ValueInput/ValueOutput block entity saves; retained inventory and EMC keys.
- Current recipe serializers, recipe displays, ingredients, and network codecs.
- Current render states, container rendering, item definitions, and armor assets.
- Server startup and datapack reload EMC mapping; updated craftable name tag and saddle defaults.
- Updated JEI, Jade, and Curios integration. Upstream update notifications are disabled
  because upstream releases target a different game version.

The migrated generated assets and data are authoritative. The old Java data
generator is retained for reference and is not a supported regeneration path yet.
CraftTweaker and EMI integrations are excluded: their author-published Modrinth
version lists have no matching Minecraft 26.1.2 / NeoForge release as of 2026-10-11.
TOP and WTHIT integrations are included and guarded by the presence of those mods.
WTHIT also requires badpackets neo-0.12.2. These HUD mods were tested in a disposable
instance; the user's existing instance continues using Jade.
The companion Mekanism `projecte.1` patch restores its ProjectE chemical serializers,
recipe mappers, and contents processor against this API. PRC and sawmill mapping
retain their upstream disabled defaults. CraftTweaker and EMI remain excluded.

## project02.3 economy and pickup follow-up

Fixed EMC seeds and custom conversion formulas now act as upper bounds while
generating values. The final integer map is checked against real crafting,
cooking, and stonecutting results and recipe-specific remainders, then corrections
are fed back through the mapping graph, including Mekanism chemical conversions.
Returned repairable tools contribute no durability cost: Repair Talismans would
otherwise permit a craft/repair/sell loop. Firework base costs and additional
fuel/stars are divided across the three rockets actually produced.

With both Mekanism and CakeStickLib loaded, coal/charcoal philosopher's-stone
recipes become 1:1. The original 1:4 recipe combined with charcoal -> carbon dust
-> Mekanism coal enrichment is an amplification cycle; merely lowering EMC would
eventually remove the whole fuel chain. The original ratios remain without this
combination. The conditional generated recipes and their advancements are the
authoritative resources; the old Java datagen source is not run for this port.

Prices can decrease from upstream defaults (for example iron 252, gold 2016,
diamond 8064). Some free/sub-unit outputs cannot retain a positive integer EMC.
When Prefab's unchanged 6 blocks <-> 4 stairs recipes are present for dirt or
grass, those stairs lose EMC (the required value is 1.5); dirt and grass blocks
retain their EMC. Their crafting recipes remain available.
Custom EMC overrides are also checked, so a deliberately unsafe override is not
guaranteed to remain fixed. Pregenerated maps receive item-recipe validation;
regenerate them after changing chemical recipes to refresh the entire graph.

The separate Titanium patch changes only PlayerInventoryFinder and its nested
classes: use Inventory indices for both reads and writes, reject invalid indices,
and mark writes dirty. Industrial Foregoing itself needs no binary change.
Source/build instructions are in `../Titanium-pickup-fix`; patched candidates are
staged in `../outputs/projecte-followup-candidates` before installation.

Current evidence is generated by `port-tools/summarize_followup.py` into
`../verification/projecte-followup/REPORT.txt`. Coverage includes integer graph
regressions, crafting with free tool repair, actual backpack pickups in main and
offhand slots, all fourteen Mekanism mapper implementations, chemical codec
roundtrips, stored-item component values, and loading Mekanism without ProjectE.

## Verification

The project02.2 baseline passed 97 tests, including all existing tests and coverage for
inventory transactions, persisted condenser targets/EMC, equipment components,
recipe synchronization, philosopher's stone remainders, and Mercurial Eye slots.

The project02.2 audit fixes five behavior groups found during testing:

- Klein Star fuel extraction and Curios fuel buffers now write modified item
  components back to the real inventory, preventing free fuel or lost buffers.
- Repair Talismans now persist repairs to player/Curios inventory slots.
- Divining Rod modes stay within each tier's supported ranges and recover from
  invalid saved modes. The maximum-EMC message now uses the correct label.
- A nearly full Mind Stone only removes as much player XP as it can store.
- Ignition places fire beside the clicked block, while retaining campfire and
  TNT ignition.

`PortGameplayAudit` exercises item saves/network codecs, charge/mode boundaries,
EMC capacities and conservation, every placeable ProjectE crafting recipe,
bag/knowledge persistence, tools, armor effects, projectiles, pedestal callbacks,
fluid placement, Time Watch acceleration, Nova drops, commands, and integrations.
Results and explicit coverage limits are recorded in
`../verification/projecte-audit/REPORT.txt`; passing the audit does not establish
that every behavior of every possible mod combination is error-free.

The optional `src/smoke` mod is never packaged in the distributable. It runs an
isolated world and checks condensers, matter furnaces, collectors, and the actual
network click that charges the final mapped EMC for one diamond. It opens and captures all
15 machine/item menus with JEI, Jade, and Curios installed.

The initial port completed the machine, network-click, and 15-menu checks with
208 existing instance mods. The follow-up audit uses the current 215 other mods
(217 test JARs including ProjectE and the disposable smoke mod), which map 3450
EMC values. A gallery of 120 registered item and active-state models was captured
and visually checked.

This is a focused functional check, not exhaustive testing of all mod interactions.
The complete combination still logs third-party JEI recipe errors involving
Twilight Forest and Functional Storage. An earlier launch had an intermittent
native crash during AAA Particles initialization; the completed run did not
reproduce it. No other installed mods were modified to suppress these issues.
Detailed evidence is in `../verification/projecte-release/REPORT.txt`.

The project02.2 report preserves the original 44 economy findings and Titanium
pickup stack trace. Those historical findings are addressed by project02.3 and
the companion Titanium/Mekanism patches described above. The GUI scenario now
also performs a real server-player pickup and verifies item conservation.

```powershell
.\gradlew.bat compileSmokeJava -PportSmoke
python port-tools/verify_release.py --minimal
python port-tools/verify_release.py --minimal --gallery
python port-tools/verify_release.py --minimal --audit --optional
python port-tools/verify_release.py --core --audit
python port-tools/verify_release.py --audit
```

`verify_release.py` uses the actual installed launcher's classpath and copies
mods, settings, native files, and a disposable test world into `.work/test-*`.
It never edits the original Minecraft JAR, libraries, assets, version metadata,
native files, or player worlds. Logs and original-file hashes are saved under
`../verification/projecte-release`. Without `--minimal` it checks the whole
installed mod combination; `--baseline` omits ProjectE and the smoke mod for
comparison.

Do not rerun the `port-tools/migrate_*.py` scripts on this tree: they document the
one-time migration and are not idempotent.
